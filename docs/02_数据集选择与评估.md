# 数据集选择与评估

## 1. 优先选择已配套配置的序列

“有配置”表示当前官方代码包含相应参数和点云处理分支，不保证任意年份、任意序列、任意下载镜像都能不修改运行。先检查 bag 话题、消息类型、相机流及标定。

| 优先级 / 数据集 | 用途和输入 | 本地官方入口 | 下载与注意事项 |
|---|---|---|---|
| 1. FAST-LIVO2-Dataset | 官方手持/场景示例，Avia + 相机 + IMU；最适合首次跑通 | `mapping_avia.launch`；`avia.yaml` + `camera_pinhole.yaml` | [原始 bag Google Drive](https://drive.google.com/drive/folders/1bf5LQ8iSxw-fD8BObZmouw7lRxNacfrA?usp=drive_link)，来自 [Global-LVBA 第 4 节](https://github.com/xuankuzcr/Global-LVBA#4-dataset-download)。可先选 Retail_Street 等短序列，以网盘实际文件为准；本次未下载、未核实每包大小/真值 |
| 2. NTU VIRAL | 无人机 LiDAR/相机/IMU/UWB，适合轨迹评价；算法配置使用一台 Ouster 和左相机 | `mapping_ouster_ntu.launch`；`NTU_VIRAL.yaml` | [官方入口](https://ntu-aris.github.io/ntu_viral_dataset/)。核对真值参考点与算法 IMU 原点，不能直接混用雷达位置、棱镜位置 |
| 3. Hilti-Oxford 2022 | 建筑、走廊、光照变化；Hesai XT32、相机、IMU | `mapping_hesaixt32_hilti22.launch`；`HILTI22.yaml` + `camera_fisheye_HILTI22.yaml` | [2022 官方数据页](https://hilti-challenge.com/dataset-2022)。首次可选 Exp14（页面约 6 GB，有 6DoF 与 3DoF 真值入口）；多数挑战序列只有稀疏位置真值，不应都当成连续 6DoF |
| 4. MARS-LVIG | 航空下视 Avia/相机/IMU/GNSS；适合高空、退化场景扩展 | `mapping_avia_marslvig.launch`；`MARS_LVIG.yaml` | [MaRS 官方数据页](https://mars.hku.hk/dataset.html)。有 HKairport、HKisland、AMtown、AMvalley 等；GNSS 是数据/评价资源，不意味着 FAST-LIVO2 默认融合 GNSS |
| 5. LIV-Eye / Mid-360 示例 | 最接近目标雷达，但配套相机是海康，不是 D455 | 主仓库没有 `mapping_mid360.launch`；需从 LIV_handhold_2 配套目录取用 | [作者团队 LIV-Eye 仓库](https://github.com/hku-mars/LIV_handhold_2#running-fast-livo2)。其数据下载入口在 Running FAST-LIVO2 段，时间同步和外参只对原设备有效 |
| 6. 自采 D455 + Mid-360 | 验证最终硬件和 PX4 准备条件 | 本资料模板 + 自己的内外参/同步配置 | 不应省略静止段、标定数据、原始时间戳、驱动版本和 PX4 ULog；需要另建真值或测量控制点 |

MARS-LVIG 配置有逐序列的 `img_time_offset`、曝光初值和建议起播时间表。HKairport/HKisland 与 AMtown/AMvalley 的相机外参不同；不能只换 bag 文件名。原始配置保存在 `../upstream/FAST-LIVO2/config/MARS_LVIG.yaml`。高空序列的传感器视角和工作距离与地面 D455 平台不同，不能直接代表自采平台效果。[数据集平台说明](https://mars.hku.hk/dataset.html)

Global-LVBA 网盘还有已处理的图像/PCD/位姿数据，这些用于离线全局优化，**不是 FAST-LIVO2 所需的原始同步 rosbag**。[Global-LVBA 数据组织](https://github.com/xuankuzcr/Global-LVBA#3-dataset-preparation)

## 2. 可扩展但不是首选的公开数据

- [R3LIVE 数据](https://github.com/hku-mars/r3live)：传感器组合接近，可以考虑转换/重新标定配置；不要默认相机模型、时间偏移与 FAST-LIVO2 示例一致。
- [Newer College](https://ori-drs.github.io/newer-college-dataset/)：含 LiDAR/视觉/惯性资源，属于需按具体版本检查流与外参的扩展目标，本次没有完成适配。
- [KITTI odometry](https://www.cvlibs.net/datasets/kitti/eval_odometry.php)：不能默认拥有本算法要求的高频 IMU/逐点时间；不要把标准里程计包直接当作 LIVO 输入。KITTI Raw 等其他版本需单独核查。
- [EuRoC](https://projects.asl.ethz.ch/datasets/doku.php?id=kmavvisualinertialdatasets)、[TUM RGB-D](https://cvg.cit.tum.de/data/datasets/rgbd-dataset)：不包含所需激光雷达输入，不适合直接复现完整 FAST-LIVO2。D455 深度图转点云也不等同于原激光前端。

## 3. 下载前后检查

1. 从以上发布方入口获取 bag、标定、真值、说明和使用条款，保持序列版本一致。网盘可能要求登录；本次只验证公开入口，未验证网盘内每个文件的可下载性。
2. 建议把原始数据放在 `FASTLIVO2_reproduction/data/<dataset>/<sequence>/`，保留原文件名；计算 SHA256，记录源链接和下载时间。
3. `rosbag info --yaml sequence.bag` 存档。应有时间重叠的图像、点云、IMU；检查图像是 raw 还是 compressed。
4. Livox 需保留 `offset_time`、`timebase`、`tag`、`line`；Ouster/Hesai 需保持点字段与本版 preprocess 一致。仅重命名 topic 不会补齐缺失字段。
5. 开始必须覆盖 IMU 初始化条件。回放多次时重启算法和录包节点，避免倒退时间污染状态。

## 4. 如何证明复现成功

| 层级 | 应保存的证据 | 能说明什么 |
|---|---|---|
| 编译通过 | 镜像/提交 SHA、构建日志、依赖版本 | 依赖可用，不代表数值正确 |
| 数据跑通 | 完整序列日志、轨迹、地图、同步错误统计 | 节点和输入基本正确 |
| 精度复现 | 对齐后 ATE、RPE、轨迹覆盖率、失败区间 | 可比较定位性能 |
| 实时复现 | 1 倍速、延迟 P50/P95、CPU/内存、队列趋势 | 在该机器和该参数下是否跟得上 |
| 实机适用 | 自采标定误差、同步抖动、长时稳定性、飞控创新量 | 硬件与飞控链路是否可用 |

使用 evo 前先统一时间单位、传感器原点和姿态约定；TUM 格式为 `timestamp tx ty tz qx qy qz qw`。LiDAR-惯性系统有公制尺度，通常使用 SE(3) 对齐，不应为了好看加入尺度拟合。示例（在已安装 evo 的环境，路径替换为实际文件）：

```bash
evo_ape tum groundtruth_imu.tum estimate.tum --align --t_max_diff 0.02 --save_results ape.zip
evo_rpe tum groundtruth_imu.tum estimate.tum --align --delta 1 --delta_unit m --save_results rpe.zip
```

`0.02 s` 是示例关联阈值，不是所有数据集统一指标；报告需记录关联数量、覆盖率和对齐方式。Hilti 稀疏 3DoF 真值应遵循其官方评测协议，不强行套完整姿态 RPE。没有真值时只能报告地图叠合、控制点和闭环返回误差，不能宣称获得 ATE 或论文同等精度。[evo 官方项目](https://github.com/MichaelGrupp/evo)

对照实验建议：同序列跑一次 LIO（`common/img_en: 0`）和一次 LIVO（`1`），其他条件不变，比较视觉加入后的精度和耗时。记录改变参数后的结果属于复现调参，不能冒充官方默认配置结果。
