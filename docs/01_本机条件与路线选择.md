## 2. 推荐路线

**官方 ROS1 对照路线：现有 Windows + Docker Desktop（WSL2 后端）+ Ubuntu 20.04 / ROS Noetic 容器。** 此对照路线无需先装 Ubuntu WSL。用户选定的 ROS2 主路线则需要独立 Ubuntu 22.04，详见 07。[Docker WSL2 文档](https://docs.docker.com/desktop/features/wsl/)

| 路线 | 用途 | 限制 |
|---|---|---|
| Docker / WSL2 后端 | 本机离线数据集、可重建依赖环境 | GUI 需额外配置；USB、UDP、PTP 不能只凭 hello-world 通过就视为可用 |
| 独立 Ubuntu 20.04 WSL2 | 需要 Linux 终端、WSLg RViz 交互 | 还需安装发行版；驱动、硬件时钟与原生 Linux 有差异 |
| 原生 Ubuntu 的 PC / 伴随计算机 | D455 USB3、雷达以太网、硬件同步、飞控闭环 | 推荐实机路线，需确认该硬件的 Linux 驱动与内核兼容 |
| Ubuntu 22.04/24.04 + ROS2 移植 | 后续长期工程维护 | 不能直接把 ROS1 launch/catkin 命令改成 ros2/colcon；须单独验证第三方移植的数值和行为 |

官方仓库给出的历史环境为 Ubuntu 18.04–20.04，PCL ≥1.8、Eigen ≥3.3.4、OpenCV ≥4.2、旧版非模板 Sophus 和指定 rpg_vikit；本资料选 20.04 + Noetic 降低版本歧义。[官方依赖说明](https://github.com/hku-mars/FAST-LIVO2#2-prerequisited)

截至核查日 Noetic 已于 2025-05-31 结束支持。它适合作为固定版本的研究复现基线；新的机载产品应另做受维护平台的迁移和回归测试，而不是将本容器视为长期维护承诺。[ROS 官方 EOL 说明](https://www.ros.org/blog/noetic-eol/)

## 3. 资源建议（工程建议，非官方最低配置）

- 单次只回放一个序列，先用 `-r 0.5` 排查输入，再用 `-r 1.0` 测实时性。
- 为 Linux/镜像/构建预留 20–40 GB，为 bag 和结果预留 100 GB 起；先下载一个短序列。Docker 镜像/volume 默认可能占 C 盘，D 盘有空间不代表 Docker 数据已迁到 D 盘。
- 首次不要将 `pcd_save.interval: -1` 配合长序列使用；这会积累全图。采用分批保存，例如 100 帧，并记录参数差异。
- 固定 CPU/内存配额，记录是否同时运行 RViz、录包、地图保存；不把桌面 CPU 的速度当作机载电脑的速度。
- GPU/CUDA 环境不是当前复现的阻塞项，无需为 FAST-LIVO2 核心算法更换显卡或安装深度学习框架。
