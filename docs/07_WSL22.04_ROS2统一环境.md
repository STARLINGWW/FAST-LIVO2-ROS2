# 统一 WSL2 Ubuntu 22.04 + ROS2 Humble 环境

> 最新整体计划采用 A（Docker20.04/Noetic 原版基准）+ B（本篇22.04/Humble移植验证）。双环境阶段、先后关系和量化验收以 [08](08_双环境原版与ROS2移植验证计划.md) 为准。本篇保留为 B 环境建设说明。

## 1. 设计判断

**合适，建议作为本机的统一机器人算法开发和离线复现主环境。** Ubuntu 22.04 (Jammy) 是 ROS2 Humble 的 Tier 1 平台，系统 Python 3.10、编译器、PCL/OpenCV 可以采用发行版配套包。Humble 支持期到 **2027 年 5 月**；以当前 2026-09 的时间看适合近期复现，但多年产品维护应规划后续 24.04/Jazzy 等迁移。[ROS REP-2000 官方版本表](https://github.com/ros-infrastructure/rep/blob/master/rep-2000.rst)

统一的对象是基础系统、工具链、ROS 发行版和版本记录；每个算法仍有独立工作区。不要把不同移植版本、同名包、不同 Sophus/OpenCV、Python 深度学习依赖全部装进一个工作区和全局 `/usr/local`。

## 3. 安装与基础验收顺序（本次未执行）

PowerShell：

```powershell
wsl --list --online
wsl --install -d Ubuntu-22.04
wsl -d Ubuntu-22.04
```

完成 Linux 用户初始化后，在 Ubuntu 内安装 ROS2 Humble，使用 [官方 Jammy deb 安装步骤](https://docs.ros.org/en/humble/Installation/Ubuntu-Install-Debs.html)。该页面若被访问保护拦截，可读 [官方文档源码](https://github.com/ros2/ros2_documentation/blob/humble/source/Installation/Ubuntu-Install-Debs.rst)。先设置 UTF-8 locale、Universe 和当前 ros2-apt-source/key，再执行：

```bash
sudo apt update
sudo apt install ros-humble-desktop ros-dev-tools python3-colcon-common-extensions \
  python3-rosdep python3-vcstool python3-venv git cmake build-essential
source /opt/ros/humble/setup.bash
sudo rosdep init       # 仅首次；若已初始化则跳过，勿覆盖已有配置
rosdep update
mkdir -p ~/repro/{drivers_ws/src,fastlivo2_ws/src,px4_ws/src,datasets,runs,manifests}
ros2 doctor --report
```

安装前可正常更新系统包，但不要在复现中途随意 dist-upgrade/升级第三方库。WSLg 基础验收运行 `rviz2`，再用两个终端分别运行：

```bash
ros2 run demo_nodes_cpp talker
```

```bash
ros2 run demo_nodes_py listener
```

确认收发和 GUI 后保存系统基线：

```bash
dpkg-query -W > ~/repro/manifests/apt-packages.tsv
python3 --version
printenv ROS_DISTRO
```

日常终端只默认 source `/opt/ros/humble/setup.bash`，按项目手动 source workspace。不要同时 source Noetic 与 Humble，也不要默认 source 多个含 `fast_livo` 的工作区。Windows Anaconda 与 WSL ROS 的系统 Python 保持分离；评估/数据转换工具使用独立 venv，不用 `sudo pip` 覆盖系统依赖。

本机 32 GB 内存，初期使用 WSL 当前约 16 GB 配额也可尝试 `-j4` 编译；不足再考虑约 20 GB 内存、8–12 个逻辑 CPU 的上限。`.wslconfig` 是多个 WSL2 发行版共享的全局配置，修改可能影响 Docker，不能为此任务盲目覆盖其他设置；修改后关机重启 WSL 会中断正在运行的容器。这里未改动资源配置。

## 4. FAST-LIVO2 的 ROS2 版本选择

官方 `hku-mars/FAST-LIVO2` 当前下载的 main 是 ROS1/catkin。ROS2 需要移植版；结果应表述为“FAST-LIVO2 的 ROS2 移植复现”，并明确 fork 和 SHA。

| 候选 | 已核对内容 | 用法建议 |
|---|---|---|
| [Robotic-Developer-Road/FAST-LIVO2，humble 分支](https://github.com/Robotic-Developer-Road/FAST-LIVO2/tree/humble) | README 明确 Ubuntu 22.04/Humble；CMake 用 ament/rclcpp、livox_ros_driver2、ROS2 Vikit | 首个源码审查/公开 bag 基线候选；还未在本机编译验证 |
| [DeepRoboticsLab/fast-livo2-deep-robotics](https://github.com/DeepRoboticsLab/fast-livo2-deep-robotics) | 含 Mid-360 系列、RealSense 与 Humble 集成说明 | 硬件集成参考；其记录的实测组合为 Mid-360s + D435i + Jetson Orin，不等于用户的 Mid-360 + D455 + PX4 已验证 |

优先从一个候选开始，不混拷不同 fork 的 launch、Vikit 与配置。第一候选本次检查了 README/CMake/package.xml，快照位于 `evidence/ros2_candidate/`。GitHub API 后续遇到限流，Git 远程查询有网络重置，所以本次**没有锁定并完整下载 ROS2 移植提交**；不能把候选当作已完成部署的版本。

构建准备路线：

1. 先安装 Humble 基础依赖，例如 `ros-humble-pcl-ros`、`ros-humble-cv-bridge`、`ros-humble-image-transport`、`ros-humble-compressed-image-transport`、`libfmt-dev`；Sophus 按该 fork 实际 API 选择。不要把 ROS1 的旧 Sophus 安装脚本直接搬进统一系统。
2. 按官方 driver2 指南安装 Livox-SDK2，在 drivers_ws 中运行 `./build.sh humble`，先验收 driver2 包。驱动的构建脚本可能清理其工作区，因此保持独立 workspace。
3. 下载选定的 FAST-LIVO2 和该移植要求的 ROS2 Vikit，并固定 SHA。候选命令如下（未执行）：

```bash
cd ~/repro/fastlivo2_ws/src
git clone --branch humble https://github.com/Robotic-Developer-Road/FAST-LIVO2.git
git clone https://github.com/Robotic-Developer-Road/rpg_vikit.git
git -C FAST-LIVO2 rev-parse HEAD
git -C rpg_vikit rev-parse HEAD
```

4. source Humble 和已编译的 drivers_ws，检查 package.xml 后用 rosdep 解析依赖，再编译：

```bash
source /opt/ros/humble/setup.bash
source ~/repro/drivers_ws/install/setup.bash
cd ~/repro/fastlivo2_ws
rosdep install --from-paths src --ignore-src -r -y --rosdistro humble
CMAKE_BUILD_PARALLEL_LEVEL=4 colcon build --symlink-install --executor sequential \
  --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
ros2 pkg prefix fast_livo
vcs export --exact src > ~/repro/manifests/fastlivo2.repos
```

以上是实施顺序，不保证候选仓库依赖声明完整。构建失败应记录错误并补充工程补丁，而不是使用 `--continue-on-error` 将部分成功当作完整通过。

## 5. ROS1 数据集迁到 ROS2 的验收点

公开数据表里的传感器信息仍有效，但 02 的 launch 文件名是官方 ROS1 配置，ROS2 fork 未必移植了全部数据集分支。第一候选 README 的示例启动名是 `mapping_aviz.launch.py`（拼写 aviz）；第二候选为 `mapping_avia.launch.py`，不可混用。

建议用独立 venv 安装 `rosbags`，用其转换能力将 bag 生成 rosbag2，并显式处理 Livox 自定义类型和依赖定义；当前工具语法以 `rosbags-convert --help` 为准。[rosbags 维护方项目](https://gitlab.com/ternaris/rosbags)

```bash
python3 -m venv ~/repro/tools/rosbags-venv
source ~/repro/tools/rosbags-venv/bin/activate
pip install rosbags
rosbags-convert --help
# 在确认自定义类型注册/映射后转换，普通调用起点如下：
rosbags-convert --src /path/to/input.bag --dst ~/repro/datasets/converted_sequence
deactivate
```

不能只改 metadata.yaml 就认定 `livox_ros_driver/msg/CustomMsg` 已正确变成 `livox_ros_driver2/msg/CustomMsg`；需检查 SQLite topics/metadata、嵌套 CustomPoint、实际 CDR 字段布局和实际订阅，保留点时间并用 `ros2 bag info` 核查。

回放前核对：

- 消息定义/字段/时间戳与算法预处理一致；图像压缩流有正确解码节点。
- 输入与订阅 QoS 匹配，`ros2 topic info -v` 查看 reliable / best_effort。必要时给 rosbag2 显式 QoS override。
- `ros2 bag play ... --clock`，并将算法及需要仿真时间的节点 `use_sim_time` 全部置 true。先用 `ros2 launch ... --show-args` 检查 launch 是否暴露该参数，不凭经验添加不存在的参数。
- `ros2 param dump <实际节点名>` 归档，确认相机 YAML 真正被该 ROS2 参数结构读取。
- 比较 ROS1/ROS2 同序列的覆盖率、轨迹误差、时间和输出帧；移植差异可能来自时间/调度/QoS，不一定是算法本身。

## 6. ROS2 实机路线

Mid-360 使用 driver2 Humble 构建与 `msg_MID360_launch.py`（以锁定驱动实际文件为准），保留 CustomMsg。RealSense 使用与 Humble 配套的 ROS2 wrapper / SDK，**不使用 04 中的 ros1-legacy**。典型 ROS2 相机 profile 参数为 `rgb_camera.color_profile:=640x480x30`，话题可能是 `/camera/camera/color/image_raw`；先 `ros2 topic list` 再填算法配置，不能沿用 ROS1 话题名猜测。

PX4 选择一条明确定义的链路：

- 原生 ROS2 路线：适配后的 `px4_msgs/VehicleOdometry` → uXRCE-DDS → `/fmu/in/vehicle_visual_odometry`。`px4_msgs`、PX4 固件和 DDS topics 配置匹配；明确 boot time、姿态顺序、pose/velocity frame、方差和 reset_counter。
- MAVROS2 路线：适配后的 ROS odometry → MAVROS2 → MAVLink ODOMETRY；按所用插件确认 ENU/FLU 与 FRD 的变换，不能再照搬 ROS1 话题及配置。

两条路线都需要 04 的机体外参、时间和质量适配。DDS 不会自动将 FAST-LIVO2 的状态变成正确飞控观测。[PX4 ROS2 指南](https://docs.px4.io/v1.16/en/ros2/user_guide)

## 7. WSL 的实机边界

| 任务 | 建议 |
|---|---|
| 编译、公开数据集、rosbag2、RViz2 | 适合作为 WSL 主用途 |
| PX4 SITL、ROS2 仿真通信 | 可以开展；需要验证 DDS discovery、网络与仿真性能 |
| D455 USB3 | 通过 usbipd-win 可做实验，需测丢帧/带宽/重连，不等于原生 USB 时序 |
| Mid-360 UDP | 可尝试镜像网络/防火墙配置，实测路由和数据；不要默认 NAT 可接收全部流量 |
| PTP 硬件时间戳、严格同步和真实飞行闭环 | 优先原生 Linux 伴随计算机；WSL 测试结果不能替代该验证 |
