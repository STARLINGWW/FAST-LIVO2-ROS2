# 本地复现操作手册

> 本篇是官方 ROS1 / Noetic 对照路线。用户最新选择的 **WSL2 Ubuntu 22.04 + ROS2 Humble 主路线见 [07](07_WSL22.04_ROS2统一环境.md)**，不要在 Humble 环境执行本篇 catkin/roslaunch 命令。

## 0. 本手册的验证边界

已实测 Docker 引擎、Ubuntu 20.04 容器启动、DNS、D 盘挂载读写。下面的 ROS 镜像构建、算法编译和数据回放是已准备的操作步骤，**本次尚未执行完整构建/回放**。不把准备好的 Dockerfile 当成已经通过编译的交付镜像。

使用固定的官方 ROS1 代码；先跑公开 bag，再移植硬件。所有 PowerShell 命令在 Windows 执行；标为 Bash 的命令在 Linux 容器/WSL 执行。

## 1. 构建 Docker 运行环境

Windows PowerShell：

```powershell
Set-Location D:\_AAA_CODE_ALL\Tech_reproduction\FASTLIVO2_reproduction
docker info
New-Item -ItemType Directory -Force data,results | Out-Null
docker build --progress=plain -f docker/Dockerfile -t fastlivo2:noetic-local . 2>&1 | Tee-Object results/build.log
if ($LASTEXITCODE -ne 0) { throw '镜像构建失败，请检查 build.log' }
docker image inspect fastlivo2:noetic-local --format '{{.Id}}' | Set-Content results/image_id.txt
```

镜像安装 Noetic/PCL/OpenCV/Eigen、官方要求的旧 Sophus 和指定 Vikit，复制本目录官方源码并 `catkin_make -j4`。旧 Sophus 的 `std::complex` setter 兼容修改只在镜像内进行；不改变 FAST-LIVO2 算法。基础 ROS tag 和 apt 包不是全版本锁定，成功后应保存镜像 ID、包清单，并按需 `docker save` 归档。源码 SHA 在总览和 06 文档中。

若遇到 ROS apt 签名/源失效，按 [ROS 官方安装入口](https://wiki.ros.org/noetic/Installation/Ubuntu) 和 [ros-apt-source](https://github.com/ros-infrastructure/ros-apt-source) 修复源配置，不能用关闭签名校验作为复现方法。Noetic EOL 不等于现有程序必然不能运行，但旧包可用性必须由实际构建确认。

创建持久开发容器（不使用 `--rm`，便于保存容器内部编译及 Log 结果）：

```powershell
docker run -dit --name fastlivo2-dev --shm-size=1g --mount 'type=bind,source=D:\_AAA_CODE_ALL\Tech_reproduction\FASTLIVO2_reproduction,target=/work' fastlivo2:noetic-local bash
docker exec fastlivo2-dev /usr/local/bin/fastlivo-entrypoint bash /work/scripts/linux_preflight.sh
docker exec fastlivo2-dev bash -lc 'dpkg-query -W > /work/results/packages.tsv'
```

若已存在同名容器，执行 `docker start fastlivo2-dev`，不要为了重跑而删除它。`/work` 是 D 盘目录；编译工作区在 `/opt/fastlivo_ws`，避免直接在 NTFS 挂载目录中完成大量小文件编译。

## 2. 下载并检查一个序列

按 02 文档获取官方原始 bag，放进 `data/`。以下命令中 `your_sequence.bag` 必须替换成实际文件名。

```powershell
Get-FileHash .\data\your_sequence.bag -Algorithm SHA256
docker exec -it fastlivo2-dev /usr/local/bin/fastlivo-entrypoint bash
```

进入容器 Bash 后：

```bash
rosbag info --yaml /work/data/your_sequence.bag > /work/results/bag_info.yaml
cat /work/results/bag_info.yaml
```

检查 `/livox/lidar`、`/livox/imu`、`/left_camera/image` 是否存在。Avia 默认相机设置对应官方相机，不适用于 D455。如果只有 `/left_camera/image/compressed`，下一步开启解压节点；如果已有 raw，就不要同时再发布同名 raw 图像。

## 3. 无界面回放：三个终端

每个新 PowerShell 终端先运行：

```powershell
docker exec -it fastlivo2-dev /usr/local/bin/fastlivo-entrypoint bash
```

终端 A（Bash，Avia 示例）：

```bash
roslaunch /work/templates/dataset.launch sequence:=first_run image_compressed:=true
```

`image_compressed:=true` 仅适用于 bag 有相应 compressed 话题的情形。此启动文件加载官方配置，开启轨迹输出、默认关闭 PCD 保存、使用仿真时钟，并把源码自带飞控输出改到 `/fastlivo2/raw_vision_pose`。没有启动 RViz。

终端 B：先等待 A 启动成功，再开始录制输出。

```bash
rosbag record -O /work/results/first_run_output.bag /aft_mapped_to_init /LIVO2/imu_propagate /path /cloud_registered /fastlivo2/raw_vision_pose
```

终端 C：

```bash
rosbag play --clock --pause -r 0.5 /work/data/your_sequence.bag
```

按空格开始。初次排错完成后，重启算法/录制节点，用新的 `sequence` 名和输出文件以 `-r 1.0` 重跑。不要在同一算法进程中循环播放导致时间回退。长序列不要一开始跳过全部静止/初始化数据；MARS-LVIG 应按其配置里的起播表处理。

回放中另开容器终端检查：

```bash
rostopic hz /aft_mapped_to_init
rostopic info /livox/lidar
rostopic echo -n 1 /aft_mapped_to_init/header
```

`rostopic hz` 用 Ctrl+C 结束后再执行后面的检查。只看到 roslaunch 不报错不足以证明复现：还应观察完整轨迹、地图、帧处理时间和是否长期堆积消息。

## 4. 保存与显示结果

回放结束后先 Ctrl+C 停止录包、再停止算法，等待文件正常关闭。

```bash
cp /opt/fastlivo_ws/src/FAST-LIVO2/Log/result/first_run.txt /work/results/first_run.tum
```

官方轨迹文件输出在 `Log/result/<seq_name>.txt`，已经是 TUM 样式。要保存点云，以 `save_pcd:=true` 重跑；模板将间隔设为 100 帧，结果在 `Log/pcd/`，复制至 `/work/results/`。这属于输出配置修改，应写入实验记录。

Docker Desktop 可以运行 Linux GUI，但本次没有验证 X11/WSLg 转发；上述命令仅验证无界面路线。需要实时 RViz 时，优先选下一节的独立 Ubuntu WSL2 + WSLg，或原生 Linux。也可以后续配置容器显示服务，不要默认 Windows 的 `DISPLAY=:0` 即可工作。

## 5. 切换数据集

使用 `templates/dataset.launch` 的 `config` 和 `camera` 参数成对替换，例如：

```bash
roslaunch /work/templates/dataset.launch \
  config:=/opt/fastlivo_ws/src/FAST-LIVO2/config/NTU_VIRAL.yaml \
  camera:=/opt/fastlivo_ws/src/FAST-LIVO2/config/camera_NTU_VIRAL.yaml \
  sequence:=ntu_run image_compressed:=false
```

Hilti 对应 `HILTI22.yaml` 与 `camera_fisheye_HILTI22.yaml`。MARS 对应 `MARS_LVIG.yaml` 与 `camera_MARS_LVIG.yaml`，还要按具体序列修改偏移/外参；先复制参数文件到 `/work/results/<run>/` 再编辑，保留上游默认配置。

也可直接使用 02 文档列出的官方 launch。但官方 Avia launch 自带图像解压节点，且所有官方 launch 对应的算法可能发布 `/mavros/vision_pose/pose`；离线实验不要与真实飞控共用未隔离的 ROS graph。

## 6. 独立 Ubuntu WSL2 备选

当前不需要它才能使用 Docker。若希望直接运行 Linux 开发工具和 WSLg RViz，可在 PowerShell 安装：

```powershell
wsl --list --online
wsl --install -d Ubuntu-20.04
wsl -d Ubuntu-20.04
```

若在线列表不再含该名称，使用 [微软官方旧版发行版安装入口](https://learn.microsoft.com/en-us/windows/wsl/install-manual)。安装后的账户初始化/系统提示按实际情况处理。本次未替用户安装该发行版。

在 Ubuntu 内按 [Noetic 官方安装步骤](https://wiki.ros.org/noetic/Installation/Ubuntu) 安装 `ros-noetic-desktop`；然后安装 Dockerfile 列出的依赖，构建 Sophus 和 Vikit，将源码复制到 Linux 自有文件系统下的 `~/fastlivo_ws/src/FAST-LIVO2`，执行：

```bash
source /opt/ros/noetic/setup.bash
cd ~/fastlivo_ws
catkin_make -j4 -l4
source devel/setup.bash
roslaunch fast_livo mapping_avia.launch
```

WSL 里 D 盘路径为 `/mnt/d/_AAA_CODE_ALL/Tech_reproduction/FASTLIVO2_reproduction`。Windows 的 Anaconda Python 不是 ROS Noetic 的 Linux Python，避免混用。源码读取/结果归档可以跨盘，编译建议在 Linux home。

## 7. 常见故障

| 现象 | 优先检查 |
|---|---|
| Docker named pipe 不存在 | Docker Desktop 是否启动；`docker info` 是否有 Server |
| 编译被 killed | 内存不足，降低 `-j`；Docker 目前只有约 15.5 GiB 配额 |
| Sophus::SE3 / 头文件不匹配 | 是否误装新版模板 Sophus；应使用官方指定 a621ff |
| 找不到 vikit | 是否使用 xuankuzcr/rpg_vikit，而不是另一同名库；是否 source 正确 workspace |
| 有点云没轨迹 | IMU 初始化、时间范围、单位、图像等待、消息 MD5/类型、字段、仿真时钟 |
| 有 LIO 没视觉约束 | 图像话题/raw/compressed、相机私有参数、分辨率、内外参、视野重叠和同步 |
| 快速运动重影/彩色边缘错位 | 逐点时间、图像偏移、外参方向、快门和曝光，不能只调滤波噪声 |
| 回放后性能不一致 | 代码 SHA、启动参数、数据校验和、CPU 占用、图像解压、PCD 保存与 GUI 差异 |

03 的命令准备不等于算法已经跑通；实际验收请按 02 的指标和实验记录模板填写。
