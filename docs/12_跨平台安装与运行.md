# 跨平台安装与运行：Windows(Docker+WSL2) 与原生 Ubuntu 22.04

本仓库的代码与脚本支持两条互不影响的运行轨道，按你手上的机器选一条即可。两条轨道共用同一套源码、
同一套评测脚本与同一套路径约定（环境变量），所以结果可以互相比较。

| 轨道 | 适用机器 | ROS1 官方基线 | ROS2 移植版 |
|---|---|---|---|
| **A** | Windows + Docker Desktop + WSL2 | Docker 容器（Noetic / Ubuntu 20.04 镜像） | WSL2 里的 Ubuntu 22.04 + Humble |
| **B** | 原生 Ubuntu 22.04（x86_64 或 ARM） | Docker 容器（同上，x86_64） | 本机直接编译运行 |

前提：仓库**不含**数据集、视频与 Docker 镜像（体积与许可原因，见 [NOTICE](../NOTICE)），
所以两条轨道都要先做"取源码 + 取数据"两步，下面分别说明。

## 0. 两条轨道都要先做的事

```bash
# 1) 取回被 pin 住的上游源码（ROS1 镜像的 COPY 源、ROS2 的 driver 依赖）
python3 scripts/fetch_pinned_sources.py          # 校验 SHA256，写入 manifests/fetched_sources.json

# 2) 数据：Hilti 官方包（exp14/exp07/exp18）+ Retail_Street
python3 scripts/download_hf_resumable.py --sequence exp14_basement_2      # 见脚本 --help
python3 scripts/prepare_hilti.py --sequence exp14_basement_2 --tag hilti_exp14   # 生成 ROS1/ROS2 两套输入
```

`prepare_hilti.py` 会同时生成 `data/derived/<tag>_3topics.bag`（ROS1）与 `data/derived/<tag>_ros2/`（ROS2），
并做逐消息往返校验；校验报告写在 `results/*_conversion_audit.json`。数据目录可用 `FASTLIVO2_DATASETS` 指定。

## 1. 轨道 A：Windows + Docker Desktop + WSL2

### 1.1 ROS1 官方基线（Docker）

```powershell
# 可选：先把 Noetic 的 deb 预取到 downloads/noetic_debs（离线/国内网络更稳）
./.venv-tools/Scripts/python scripts/prefetch_debs.py

# 构建镜像（在仓库根目录执行；镜像固定 Noetic 基础镜像 digest）
docker build -f docker/Dockerfile -t fastlivo2:noetic-local .

# 启动长期容器（把仓库挂载到 /work）
docker run -d --name fastlivo2-ros1 -v ${PWD}:/work fastlivo2:noetic-local sleep infinity

# 数据放进容器的 /datasets（容器可写层，不进镜像）
docker cp data/raw/Retail_Street_from_ros2_mirror.bag fastlivo2-ros1:/datasets/
docker cp data/derived/hilti_exp14_3topics.bag fastlivo2-ros1:/datasets/

# 跑一次 1× 回放
docker exec fastlivo2-ros1 /usr/local/bin/fastlivo-entrypoint python3 /work/scripts/run_ros1_bag.py `
    /datasets/hilti_exp14_3topics.bag hilti_ros1_1x_01 --rate 1.0 --dataset HILTI22
```

### 1.2 ROS2 移植版（WSL2 Ubuntu 22.04）

```powershell
wsl -d FASTLIVO-Ubuntu-22.04 -u livo      # 进入发行版（发行版需要自己先装好 Ubuntu 22.04 + Humble）
```

```bash
cd /mnt/d/_AAA_CODE_ALL/Tech_reproduction/FASTLIVO2_reproduction     # 或你的克隆位置
scripts/install_deps_ubuntu2204.sh        # 首次：ROS2 Humble + PCL/Eigen/OpenCV/Sophus 等
scripts/build_ros2_workspace.sh           # 编 Livox-SDK2 + 组装工作区 + colcon build
python3 scripts/run_ros2_bag.py $HOME/repro/datasets/hilti_exp14_ros2 hilti_ros2_1x_01 \
        --rate 1.0 --dataset HILTI22 --output-root results/runs
```

### 1.3 Windows 侧驱动脚本

`scripts/run_validation_matrix.ps1`、`run_showcase_matrix.ps1`、`run_exp07_paper_matrix.ps1`、
`run_vio_sensitivity.ps1`、`run_lidar_ablation_matrix.ps1` 会 dot-source `scripts/site.ps1`，
自动推导 WSL 路径、发行版名、容器名；无需再改脚本。

### 1.4 冷启动与故障

* Docker Desktop 冷启动崩溃（残留 socket）：`powershell -File scripts\fix_docker_desktop_stale_sockets.ps1`，机理见 [05](05_Docker_WSL检测.md)；
* 同一时刻只允许一个算法节点，规则与原因见 [11](11_冷启动与并发运行规则.md)；
* ROS1 镜像的可恢复性：`data/image_archives/*.tar`（`docker load -i`），见 [05](05_Docker_WSL检测.md)。

## 2. 轨道 B：原生 Ubuntu 22.04

### 2.1 依赖

```bash
scripts/install_deps_ubuntu2204.sh --check      # 先看缺什么，不改系统
scripts/install_deps_ubuntu2204.sh              # 安装缺的包（ROS 未装时给官方指引，或加 --auto-ros）
APT_MIRROR=mirrors.aliyun.com scripts/install_deps_ubuntu2204.sh   # 国内镜像
```

依赖版本参照我们实测通过的组合：`libpcl-dev 1.12.x`、`libeigen3-dev 3.4.0`、`libopencv-dev 4.5.4`、
`libfmt-dev 8.1.1`、`ros-humble-sophus`、`ros-humble-{cv-bridge,image-transport,pcl-ros,pcl-conversions,tf2-ros}`。

### 2.2 构建 ROS2 工作区

```bash
python3 scripts/fetch_pinned_sources.py         # 需要 upstream/ 里的 driver2 与 Livox-SDK2
scripts/build_ros2_workspace.sh                 # 默认 $HOME/repro/fastlivo2_ws
FASTLIVO2_WS=$HOME/xplat_ws scripts/build_ros2_workspace.sh --jobs 6   # 指定别的工作区
```

脚本做的事：检查源码与 ROS → 编译并安装 Livox-SDK2（已装则跳过）→ 把 `ros2/FAST-LIVO2`、`ros2/rpg_vikit`、
`upstream/livox_ros_driver2` 同步进 `<workspace>/src`（driver2 会自动切到 ROS2 的 `package.xml`/`launch`）
→ `colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release -DROS_EDITION=ROS2 -DDISTRO_ROS=humble`。

### 2.3 运行与评测

```bash
source /opt/ros/humble/setup.bash && source $FASTLIVO2_WS/install/setup.bash

python3 scripts/run_ros2_bag.py <bag 目录> <run_id> --rate 1.0 --dataset HILTI22 --output-root results/runs

# 与真值/另一实现对拍
python3 scripts/evaluate_trajectories.py <参考.tum> results/runs/<run_id>/trajectory.tum \
        --reference-kind ros1_baseline --output results/comparisons/<name>

# 成果自检（视频/点云/报告链接）与"报告数字"独立复核
python3 scripts/verify_final_artifacts.py
python3 scripts/audit_report_claims.py
```

`run_ros2_bag.py` 自带两条门槛：轨迹覆盖率 ≥ 0.99 才算有效；发现同 ROS 域里已有算法/回放进程会拒绝启动（避免互相污染）。

### 2.4 ARM（Jetson 等）说明

ROS2 侧源码带 aarch64 分支（`-O3 -mcpu=native -ffast-math`），但**我们没有在 ARM 上实测过**：
先在目标机上跑我们归档的 bag 做回归（覆盖率与耗时），再接真实传感器；算力参考值是论文在 ARM 平台上的
94 ms/帧（Long Corridor），本机 x86 是 18–32 ms/帧，详见 [10](10_论文对照与多数据集成果.md) 与 [04](04_D455_Mid360_PX4实施方案.md)。

## 3. 路径与环境变量约定

Linux 侧脚本读 `scripts/site_config.py`，Windows 侧驱动读 `scripts/site.ps1`；两者都可以用环境变量覆盖：

| 变量 | 含义 | 默认值 |
|---|---|---|
| `FASTLIVO2_PROJECT` | 仓库根目录 | 脚本自身推导 |
| `FASTLIVO2_WS` | ROS2 工作区 | `$HOME/repro/fastlivo2_ws`（容器内 `/opt/fastlivo_ws`） |
| `FASTLIVO2_DATASETS` | bag 所在目录 | `$HOME/repro/datasets`（容器内 `/datasets`） |
| `FASTLIVO2_RECORDED` | ROS2 可视化录制目录 | `$HOME/repro/recorded` |
| `FASTLIVO2_RESULTS` | 运行输出根目录 | `<repo>/results/runs` |
| `FASTLIVO2_ROS1_MOUNT` | 容器里挂载仓库的路径 | `/work` |
| `FASTLIVO2_WSL_DISTRO` / `FASTLIVO2_WSL_USER` / `FASTLIVO2_ROS1_CONTAINER` | Windows 侧：发行版、用户、容器名 | `FASTLIVO-Ubuntu-22.04` / `livo` / `fastlivo2-ros1` |

## 4. 装好没有？三条验证

```bash
# 1) 二进制存在
ls $FASTLIVO2_WS/install/fast_livo/lib/fast_livo/fastlivo_mapping

# 2) 跑一次 0.5× 短回放（Hilti Exp14 约 74 s 数据）
python3 scripts/run_ros2_bag.py $FASTLIVO2_DATASETS/hilti_exp14_ros2 verify_build_01 \
        --rate 0.5 --dataset HILTI22 --output-root results/runs
#    期望：run.json 里 status=playback_completed、algorithm_exit_after_signal=0、trajectory_coverage_fraction ≥ 0.99

# 3) 评测脚本能跑通
python3 scripts/evaluate_trajectories.py data/raw/HILTI22/exp14_basement_2_imu.txt \
        results/runs/verify_build_01/trajectory.tum --reference-kind ground_truth \
        --output results/comparisons/verify_build_01
```

## 5. 常见问题

| 现象 | 原因与处理 |
|---|---|
| `vikit_common` 找不到 Sophus | 装 `ros-humble-sophus`；若曾手工装过旧版，清掉 `/usr/local/include/sophus` 与 `/usr/local/lib/cmake/Sophus` 再装 |
| x86 上长回放后 SIGSEGV | 上游用 `-march=native` 导致 Eigen/PCL 分配 ABI 不一致，我们的补丁已改为 `-march=x86-64` 并统一 `EIGEN_MAX_ALIGN_BYTES=16`；若自行改回 native 会复现 |
| 回放"跑完"但轨迹很短 | 节点落后于回放：脚本会判 `incomplete_coverage`。同机只跑一个算法节点，必要时降到 0.5× |
| ROS1 容器里 `roscore` 起不来 | 上次残留的 master 还在：`docker exec fastlivo2-ros1 pkill -f rosmaster` 后重跑（新版 runner 会直接拒绝启动而不是静默接入旧 master） |
| 数据从哪来 | 见第 0 节；Hilti 为 CC BY-NC-SA 3.0（非商用），Retail 镜像许可不明，因此本仓库不分发数据 |
